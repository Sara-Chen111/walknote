# 行记 WalkNote — 不赶场的旅行计划本

> **按每日步数预算排行程，把打卡动作写进计划**——不赶场，出好片，行后一键生成 H5 旅行手记。
> 产品哲学：体力是行程的一等约束；打卡不是目的地的附赠，而是计划的一部分。

🌐 **在线体验：https://sara-chen111.github.io/walknote/** （手机打开体验最佳；所有数据只存在你自己的浏览器里，不上传任何服务器）

## 三大板块

1. **规划台**（生成计划的入口）——输入往返时间节点、必去/次选景点、**每日步数档位（1 万/2 万/3 万步）**与交通档次（纯步行 / 公交地铁 + 步行 / 打车为主），生成逐日行程；住宿↔景点、景点↔景点的每段路都标注步行距离与步数，超预算就地提示；支持**分段住宿**（每天可设不同的出发地与当晚住宿，换宿日自动标记）
   - 内置 **攻略采集箱**：把小红书攻略粘贴/截图「分享」给行记 → AI 解析成景点 + 打卡建议 → 人工确认后进景点池
2. **计划本**（呈现计划的入口）——一天一页：时间轴 + 地点 + 打卡动作（机位/构图/姿势/时段/文案）+ 打卡照片 + 完成勾选；行中离线可用（数据在本机）
3. **展页**（H5 分享）——行后一键生成手记：按天分页、照片、步数统计、同款对比（攻略参考图 vs 自己拍的），导出单文件 HTML

数据流：攻略采集箱 → 规划台 → 计划本 → 展页，**「步数预算」是全系统流转的一等约束**。

## 快速开始

```bash
npm install --registry=https://registry.npmmirror.com
npm run dev
```

打开 http://localhost:5190 。**不配置任何 Key 也能完整体验**：内置「上海 4 天」（国内）、「东京 5 天」（海外）与「箱根·富士山 5 天」（分段住宿示例）三套演示行程（行程卡 → 编辑 → 载入），行程编排走本地规则引擎，攻略解析与文案撰写返回内置示例（演示模式）。

正式使用请在「设置」中配置：

| 配置项 | 用途 | 获取方式 |
|---|---|---|
| OpenAI 兼容 API Key（文本模型） | AI 编排行程、解析攻略、撰写手记 | GLM / DeepSeek / Kimi 等，BYOK，Key 仅存本机浏览器 |
| 视觉模型（可选） | 解析攻略截图、打卡点评（轻微多模态） | 如 `glm-4v-flash` |
| 高德 Web 服务 Key（国内行程） | 境内按真实路网算步行距离，公交段取真实换乘数据 | lbs.amap.com 个人认证后创建「Web 服务」Key，免费 15 万次/月；不配置则直线估算 |
| OpenRouteService Key（海外行程） | 境外按步行路网计算真实步数 | openrouteservice.org 免费注册（2000 次/日）；不配置则直线估算 |

引擎按坐标自动选源：境内走高德、境外走 ORS，未配置的一侧标注「估算值」。

> 当前代码为 v0.1 骨架：三大板块全流程已跑通（浏览器实测见 docs/02 附录），步数引擎已支持国内（高德）/ 海外（ORS）双模式。国内平台接入评估与商业化方向见 docs/03 第 5 节、docs/00 第 9 节。

## 技术栈

Vite + React 纯前端单页应用；localStorage 存行程、IndexedDB 存打卡照片；OpenAI 兼容协议直连（BYOK）+ 高德（境内）/ OpenRouteService（境外）双路网步数引擎。零后端、零服务器成本。

## 部署

推送到 `main` 分支即自动部署到 GitHub Pages（`.github/workflows/deploy.yml`：`npm ci` → `npm run build` → 发布 `dist/`）。`vite.config.js` 的 `base: './'` 让同一份构建既能本地运行也能挂在 `/walknote/` 子路径下。本地验证：`npm run build && npm run preview`。

## 合规红线

小红书数据只走「用户主动导入」路径（用户把攻略分享给 App 读懂），不做自动抓取、不留存原文；国内 OTA 只接官方面向个人开放的通道（飞猪 FlyAI、携程问道、联盟 CPS 链接），美团/大众点评不做任何抓取——原因与判例见 [docs/03](docs/03-数据源与合规方案.md)。
